Its own robots.txt for a single site or for every site of a multisite network – edited in the admin or deployed as a file.

== Description ==

WordPress generates a virtual robots.txt with the same rules for every site. shawesome robots.txt lets you replace it – on a single site, or separately for every site of a multisite network, e.g. to block a staging domain or to point each site to its own sitemap.

**Edit in the admin**

The plugin page is under *shawesome → robots.txt* (in a network in the network admin) and has three tabs: *robots.txt*, *Settings* and *FAQ*. On a single site, the robots.txt tab shows the editor. In a network, it lists all sites with their mode, the source of their robots.txt, the override file name, the active SEO plugins and a status, and every site has its own editor. Next to the editor, the live robots.txt shows what crawlers currently get. The content is stored in the site's database options – it survives domain changes and is removed together with the site. Leave it empty to keep the robots.txt generated by WordPress and SEO plugins.

Two buttons help with the content: one inserts example rules (the WordPress default plus the sitemap of the site), the other adds a block that stops crawlers collecting content for AI training (GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, CCBot). AI search crawlers such as OAI-SearchBot, Claude-SearchBot and PerplexityBot are not blocked. Like all of robots.txt, this only works with crawlers that follow it.

**Options per site**

The editor of each site also sets:

* the mode (see below)
* a Crawl-delay (off by default, 10 seconds when switched on; Google ignores it, Bing and Yandex for example follow it)
* resources and assets: CSS and JavaScript files, images and PDF files are allowed by default; when switched off, Disallow lines block them

Crawl-delay and blocked resources are added at the end of the robots.txt as a group for all crawlers (`User-agent: *`), in both modes. Crawlers that have a group of their own in the robots.txt do not read it.

**Or deploy a file**

A plain text file in `/wp-content/shawesome-robots-txt/` overrides the database content, e.g. for Git-based deployments. The file name is derived from the site's domain, with dots replaced by hyphens:

* `www.example.com` → `www-example-com.txt`
* `shop.example.com` → `shop-example-com.txt`

As an unambiguous alternative, the domain with dots is accepted as well (`www.example.com.txt`); the hyphenated name takes precedence. While a file exists, the editor shows its content read-only and offers to copy it into the database.

**Which sites get their own robots.txt**

Crawlers only request robots.txt from the root of a host. A site gets its own robots.txt if its address has no path:

* a single site at the root of its domain
* every site of a network with subdomains or domains
* in a network with subdirectories: the main site and sites with their own domain

Sites with a path (`example.com/blog/`) are served by the robots.txt of their host. By default, the plugin adds rules for them there – also in "Exact" mode, and it can be switched off:

* `Disallow: /blog/` for sites hidden from search engines (WordPress only adds `noindex` to their pages)
* `Sitemap: https://example.com/blog/wp-sitemap.xml` for public sites

The Disallow lines are added as a group for all crawlers (`User-agent: *`). Crawlers that have a group of their own in the robots.txt do not read it.

**Works with Yoast SEO and All in One SEO**

Yoast SEO and All in One SEO change the robots.txt output. The mode decides how your content is combined with them. The default mode is set in the settings; each site can choose its own in its editor:

* **Base** (default) – the content replaces the WordPress default; Yoast SEO removes the WordPress default rules (`User-agent: *`, `Disallow: /wp-admin/`, `Allow: /wp-admin/admin-ajax.php` in exactly this order) and appends its own rules and sitemap, All in One SEO rebuilds the rules (comments and Sitemap lines are dropped). Duplicate Sitemap lines are removed.
* **Exact** – the content is delivered as is, after all SEO plugins have run. Sites without a custom robots.txt (no content in the editor and no file) keep the one from WordPress and the SEO plugins.

**Status**

The status requests the robots.txt of each site as crawlers get it and shows whether all crawlers are blocked, how many sitemaps are linked, whether crawlers that collect content for AI training are blocked, and problems such as an unreachable robots.txt. The result is kept for a time set in the settings (24 hours by default); when the overview is opened after that time, outdated sites are checked again in the background. Each site or all sites can be checked again at any time.

**Physical robots.txt**

If a `robots.txt` file exists in the web root, the web server delivers it and WordPress is never asked. The robots.txt tab shows its content and – if WordPress may write to the web root – offers to rename it to `_old-robots.txt`, optionally after copying its content into the editor. The file is never deleted.

**Search engine visibility**

Sites set to "Discourage search engines from indexing this site" keep the WordPress default instead of the custom robots.txt, so a staging site does not deliver the rules of production – even if the database was copied from there. This can be switched off.

**Notes**

* A UTF-8 BOM is stripped and line endings are normalized.
* In a network, the plugin is network-activated and the settings apply to all sites.
* The status is requested from the site itself (a loopback request). Some servers block such requests; the status then says so.

**For developers**

* Constant `SHAWESOME_ROBOTS_TXT_DIR` or filter `shawesome_robots_txt_dir` – change the directory for override files.
* Filter `shawesome_robots_txt_candidate_files` – change the candidate file paths for a domain.
* Filter `shawesome_robots_txt_priority` – change the priority of the `robots_txt` filter.
* Content, mode, status and the options per site are stored in the site options `shawesome_robots_txt_content`, `shawesome_robots_txt_mode`, `shawesome_robots_txt_status` and `shawesome_robots_txt_rules` (not autoloaded).
* All callbacks are named functions and can be removed with `remove_filter()`.

== Installation ==

1. Upload the folder `shawesome-robots-txt` to `/wp-content/plugins/` or install the plugin via *Plugins → Add New*.
2. Activate the plugin – in a network, network-activate it.
3. Edit the robots.txt under *shawesome → robots.txt* (single site) or *Network Admin → shawesome → robots.txt* (network) – or place a text file per domain in `/wp-content/shawesome-robots-txt/`, e.g. `www-example-com.txt`.
4. Check the result with the "Open live robots.txt" link or at `https://www.example.com/robots.txt`.

== Frequently Asked Questions ==

= My robots.txt is not delivered. =

Check on the robots.txt tab that there is no physical `robots.txt` in the web root and that the site is not set to "Discourage search engines". In a network, the overview shows the source and the status of every site. For files, check that they are readable by the web server.

= I changed the content in the editor, but the old one is still delivered. =

A file in `/wp-content/shawesome-robots-txt/` overrides the database content. Delete the file – or copy it into the database first with the button in the editor.

= Yoast SEO or All in One SEO changes my robots.txt. =

Select the mode "Exact" in the settings. The content is then delivered after all SEO plugins have run.

= What does the status check? =

It requests the robots.txt of the site as crawlers get it and shows whether all crawlers are blocked, how many sitemaps are linked and whether crawlers that collect content for AI training are blocked. The result is kept for the time set in the settings and can be checked again at any time.

= Does it work if WordPress is installed in a subdirectory? =

If the address of the site contains a path (`example.com/blog/`), crawlers request the robots.txt from `example.com/robots.txt`, which WordPress does not deliver. The plugin then does nothing and says so. If only the WordPress files are in a subdirectory and the address is the root of the domain, it works.

= What happens on uninstall? =

The settings and the content stored in the database are deleted. Files in `/wp-content/shawesome-robots-txt/` and a renamed `_old-robots.txt` are kept.
